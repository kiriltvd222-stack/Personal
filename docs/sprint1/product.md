# Характеристика продукту та контексту: «Персонал+»

**Продукт:** Система управління персоналом (HRM) «Персонал+»  
**Спринт:** Спринт 1 «Продукт і вимоги»  
**Автори:** Сиротін Максим, Ходячих Нікіта, Кудря Кіріл  

## 1. Профіль компанії та продукту
* **Назва продукту:** «Персонал+» (HRM-система).
* **Призначення:** Автоматизація кадрового обліку, управління відпустками та табелювання для організацій (100–1000 працівників). 
* **Контекст спринта:** Відділ QA виокремлено після інцидентів з модулем відпусток. Мета — моделювання процесів та беклог вимог для функції *самообслуговування працівників у питаннях відпусток*.

## 2. Користувачі та ролі
| Роль | Що робить у продукті | Приклад |
| :--- | :--- | :--- |
| **Працівник** | Подає заявки на відпустку, перевіряє баланс, заповнює табель. | Дмитро подає заявку на 2 тижні |
| **HR-менеджер** | Веде картки працівників, призначає відпусткові права. | Олена додає нового працівника |
| **Керівник підрозділу** | Погоджує або відхиляє заявки та табелі підлеглих. | Тарас погоджує заявки своєї команди |
| **Адміністратор** | Керує обліковими записами та налаштуваннями. | Ігор створює обліковий запис |

| № | Пул / доріжка | Тип елемента | Назва й опис |
| :-: | :--- | :--- | :--- |

## 4. Замовлення й очікування
> **Текст:** «HR-менеджери тонуть у заявках. Зробіть самообслуговування: працівник сам бачить баланс і подає заявку, керівник погоджує одним натисканням, команда бачить, хто коли відсутній.»

**Очікування:**
1. Працівник бачить баланс відпустки з урахуванням нарахованих днів.
2. Система рахує робочі дні і блокує перевищення балансу.
3. Керівник погоджує/відхиляє заявку з коментарем.
4. Календар команди показує відсутності та попереджає про накладання.
5. Керівник отримує нагадування про непогоджені заявки, а працівник — сповіщення про статус.
6. HR-менеджер бачить звіт по залишках відпусток.
