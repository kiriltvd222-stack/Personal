# Опис продукту та Бізнес-процесів HRM-системи «Персонал+»

## Опис бізнес-процесів (BPMN 2.0)

Нижче наведено детальні специфікації елементів бізнес-процесів для їх подальшого моделювання та тестування.

---

### Модель 1: Подання й погодження відпустки

Процес охоплює функціонал подачі заявки працівником, автоматичну перевірку системою, погодження керівником та можливу ескалацію.

**Шлюзи:** Виключне АБО за даними (Data-based XOR), Виключне АБО за подіями (Event-based XOR).

| № | Пул / доріжка | Тип елемента | Назва й опис |
| :---: | :--- | :--- | :--- |
| **1** | Працівник | Початкова подія (проста) | «Працівник подав заявку на відпустку» |
| **2** | Працівник | Задача | «Обрати тип відпустки та дати» |
| **3** | Працівник | Задача + кидальна подія-повідомлення | «Надіслати заявку» (потік повідомлень до кроку 4) |
| **4** | Система | Початкова подія-повідомлення | «Отримано дані заявки» |
| **5** | Система | Задача | «Розрахувати тривалість у робочих днях» |
| **6** | Система | Шлюз XOR за даними | «Баланс достатній?» -> «ні» (до 7); -> «так» (до 8) |
| **7** | Система | Задача + кидальна подія | «Надіслати відмову» (повідомлення Працівнику) -> Кінцева подія «Відхилено системою» |
| **8** | Система | Задача + кидальна подія | «Надіслати керівнику на погодження» (повідомлення до 9) |
| **9** | Керівник | Початкова подія-повідомлення | «Отримано запит на погодження» |
| **10** | Керівник | Шлюз XOR за подіями (Event-based) | Очікування рішення або спливання часу.<br>• **Гілка 1:** Проміжна подія-повідомлення «Отримано рішення» (до 11).<br>• **Гілка 2:** Проміжна подія-таймер «Минуло 3 дні» (до 12). |
| **11** | Керівник | Шлюз XOR за даними | «Яке рішення?» -> «Погоджено» (до 13); -> «Відхилено» (до 14) |
| **12** | Керівник | Задача | «Ескалація до HR» (повідомлення HR-менеджеру) -> Кінцева подія «Передано HR» |
| **13** | Керівник | Задача + кидальна подія | «Підтвердити відпустку» -> Кінцева подія «Погоджено» |
| **14** | Керівник | Задача + кидальна подія | «Повернути з коментарем» -> Кінцева подія «Відхилено керівником» |
| **15** | Система | Згорнутий підпроцес | «Списати дні з балансу та оновити календар» (Спрацьовує після повідомлення від кроку 13) |
| **16** | Система | Кінцева подія | «Відпустку оформлено» |

---

### Модель 2: Звільнення (Offboarding)

Процес описує процедуру звільнення працівника з розгалуженням на паралельні задачі між різними відділами (HR, IT, Бухгалтерія).

**Шлюзи:** Виключне АБО (XOR), Паралельний (AND).

| № | Пул / доріжка | Тип елемента | Назва й опис |
| :---: | :--- | :--- | :--- |
| **1** | HR-менеджер | Початкова подія | «Отримано заяву або рішення про звільнення» |
| **2** | HR-менеджер | Задача | «Зареєструвати дату звільнення» |
| **3** | HR-менеджер | Шлюз XOR за даними | «Хто ініціатор?» -> «Працівник»; -> «Компанія» (Обидві гілки сходяться у синхронізуючому XOR перед кроком 4) |
| **4** | HR-менеджер | Шлюз AND (розгалуження) | Паралельний запуск трьох задач (до 5, 6, 7) |
| **5** | Керівник підрозділу | Задача | «Прийняти справи та передати проєкти» |
| **6** | Адміністратор | Задача | «Спланувати блокування облікового запису» |
| **7** | Бухгалтерія | Задача | «Розрахувати компенсацію за невикористану відпустку» |
| **8** | HR-менеджер | Шлюз AND (синхронізація) | Чекає завершення всіх трьох гілок (5, 6, 7), після чого активує вихідний потік (до 9) |
| **9** | Працівник | Задача | «Повернути робоче майно (ноутбук, перепустка)» |
| **10** | HR-менеджер | Задача | «Оформити фінальні документи» |
| **11** | HR-менеджер | Задача | «Перевести картку працівника у статус "звільнений"» |
| **12** | HR-менеджер | Кінцева подія | «Звільнення оформлено» |
