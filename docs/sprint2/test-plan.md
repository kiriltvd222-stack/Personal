## 1. Продукт і межі тестування

**Що тестуємо.** Дві частини продукту «Персонал+»:
1. **Demo-застосунок** — OrangeHRM, `https://opensource-demo.orangehrmlive.com`: панель входу та модулі Admin (користувачі), PIM (працівники), Leave (відпустки), Time (табелі), Recruitment (вакансії, кандидати), My Info. Ролі: Працівник, Керівник підрозділу, HR-менеджер, Адміністратор.
2. **Модуль бізнес-логіки** — Java 17, пакет `ua.kpi.tzyapz.personal`: класи `LeaveCalculator`, `PayrollCalculator`, `EmployeeValidator`.

**Що перевіряємо в них.** Вимоги SRS 1.1: функціональні F-10…F-140, інтерфейс GUI-10…GUI-90, бізнес-логіку BL-10…BL-80, нефункціональні P-, S-, U-, D-. Правила обчислення відпусток, нарахувань зарплати та валідації персональних даних реалізовані в Java-модулі, тому вони детально перевіряються на модульному рівні та інтеграційному.

**Поза обсягом (SRS 1.2):** Модулі Performance, Directory, Claim і Buzz у версії 1.0 не специфікуються. Також поза обсягом інтеграції із зовнішніми сервісами (SMS-шлюзи, ДПС, портали вакансій) та мобільний застосунок (п. 2.3).

**Правила роботи з публічним demo.** Власні записи працівників та кандидатів створюємо з префіксом `QA_` (наприклад, `QA_Ivan`), щоб не плутати їх з даними інших команд; не змінюємо й не видаляємо чужих записів; не змінюємо пароль загального адміністратора (`admin123`); використовуємо лише вигадані персональні дані. Навантажувальне тестування (більше 50 користувачів) та техніки перебору паролів (ZAP) на публічному demo виконуються обережно або лише на локальному Docker-резерві (якщо такий буде надано).

**Логіка пріоритетів.** Продукт — це корпоративна HRM-система, що оперує персональними даними та фінансами. Тому найвищий пріоритет мають функції розрахунку зарплат/відпусток (BL), захищеність системи (недопущення доступу до чужих профілів) та потоки даних заявок на відпустку. Інтерфейсні й експлуатаційні типи йдуть після них.

## 5. Інструменти, середовище, тестові дані

**Середовища.**
* **Demo:** `https://opensource-demo.orangehrmlive.com` (маршрут входу `/web/index.php/auth/login`; публічне середовище, дані періодично скидаються).
* **Модуль бізнес-логіки:** окремий Java-проєкт без графічного інтерфейсу, пакет `ua.kpi.tzyapz.personal` (класи `LeaveCalculator`, `PayrollCalculator`, `EmployeeValidator`), середовище виконання — JDK 17, збірка — Maven.

**Інструменти.** Chrome і Firefox (поточні версії) з DevTools; Postman (для API); Apache JMeter (для навантажувального P-20); OWASP ZAP; JUnit 5 та Mockito; IntelliJ IDEA; Excel / Google Sheets; GitHub.

**Тестові дані.**
* **Адміністратор demo:** `Admin` / `admin123` (спільний обліковий запис, пароль не змінюємо).
* **Працівники:** створюємо самі з префіксом `QA_` (наприклад, `QA_Ivan`), щоб чужі тестувальники не використовували наші записи.
* **Персональні дані:** лише вигадані ПІБ, email, телефони.
* **Межові значення полів:** 
    * *Пароль (S-10, GUI-50):* 7, 8, 9, 64 символи.
    * *РНОКПП (BL-80):* 9, 10, 11 цифр; наявність літер.
    * *Вік на дату найму:* 15, 16, 17 років.
* **Дати (для розрахунку відпусток BL-30):**

| Дата | День тижня | Призначення перевірки |
| :--- | :--- | :--- |
| `2026-10-16` | п'ятниця | заїзд перед вихідними |
| `2026-10-17` | субота | вихідний день (не має рахуватися) |
| `2026-10-16` → `2026-10-19` | пт → пн | інтервал через вихідні: має бути рівно 2 робочі дні (пт, пн) |
